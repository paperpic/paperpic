# 성능과 지원 환경

휴대폰 사진은 12메가픽셀 이상이고, 이를 편집하는 데는 실제로 많은 처리가 필요합니다. 이 페이지는 그 처리가 어디에서 이루어지는지, 빌드와 서버에 무엇이 필요한지, PaperPic이 어떤 브라우저를 지원하는지 설명합니다.

## Web Worker가 작업합니다

‘정리’와 ‘기울기 보정’은 휴대폰에서 12메가픽셀 사진을 처리할 때 1초 넘게 걸립니다. 메인 스레드에서 처리하면 그동안 페이지가 멈춥니다. 그래서 PaperPic은 이를 Web Worker에서 실행하고, 적용하는 동안에도 페이지가 계속 반응합니다.

worker는 패키지에 들어 있으며 표준 `new Worker(new URL(…, import.meta.url))`로 시작합니다. Vite와 webpack 5 같은 번들러는 설정 없이 이를 처리합니다. worker를 시작할 수 없으면 편집이 메인 스레드에서 실행됩니다. 여전히 동작하지만, 큰 이미지에서는 페이지가 잠깐 멈출 수 있습니다.

## Content Security Policy

Content Security Policy를 쓴다면 다음을 허용하세요.

- worker를 위한 `worker-src 'self'`.
- `img-src blob:`. 뷰어가 첨부 파일과 적용 결과를 `blob:` URL로 보여 주기 때문입니다.

## 큰 사진

- **편집하는 동안**에는 미리보기가 약 2메가픽셀 사본으로 처리하므로, 어떤 사진에서도 눈금자와 도구가 부드럽게 동작합니다.
- **적용할 때**는 모든 변경을 원본 해상도로 계산합니다. 큰 사진은 몇 초가 걸리므로, 그동안 뷰어가 메시지를 보여 주고 컨트롤을 잠급니다.
- **시간과 메모리를 아끼려면** [`maxOutputSize`](../reference/options#maxoutputsize)를 설정하세요. 2000이나 3000픽셀 같은 한도면 문서는 읽기 좋게 유지되고, 적용은 빨라지며 파일은 작아집니다.

## 받는 이미지

`src`에는 페이지와 같은 출처의 URL이나, 클라이언트에서 첨부한 `File` 또는 `Blob`을 지정합니다. PaperPic은 이미지의 픽셀을 읽는데, 브라우저는 다른 출처의 이미지에 대해서는 CORS를 거칠 때만 이를 허용하며, PaperPic은 CORS를 요청하지 않습니다. 이미지를 여러분의 도메인에서 제공하거나, 직접 가져와서 `Blob`을 전달하세요.

## 서버 사이드 렌더링

PaperPic에는 브라우저가 필요합니다. Vue와 React 컴포넌트는 Nuxt나 Next.js 같은 서버에서 빈 요소를 렌더링하고, 브라우저에서 뷰어를 만듭니다. 코어를 쓴다면 컴포넌트가 마운트될 때처럼 브라우저에서 직접 뷰어를 만드세요.

## 지원 브라우저

PaperPic은 [Baseline Widely Available](https://web.dev/baseline) 브라우저를 지원합니다. 모든 주요 브라우저에서 30개월 이상 동작해 온 기능들입니다. 패키지는 이 대상, 즉 Chrome과 Edge 124, Firefox 125, Safari 17.5 이상에 맞춰 빌드되므로 트랜스파일할 필요가 없습니다.
