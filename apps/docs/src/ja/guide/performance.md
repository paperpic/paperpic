# パフォーマンスと対応環境

スマートフォンの写真は 12 メガピクセル以上あり、その編集は本格的な処理です。このページでは、その処理がどこで行われるか、ビルドとサーバーに何が必要か、PaperPic がどのブラウザーに対応しているかを説明します。

## 処理は Web Worker で行う

「クリーンアップ」と「傾き補正」は、スマートフォンで 12 メガピクセルの写真を処理すると 1 秒以上かかります。メインスレッドで行うと、その間ページが固まってしまいます。そのため PaperPic はこれらを Web Worker で実行し、適用中もページは操作に応え続けます。

worker はパッケージに含まれ、標準の `new Worker(new URL(…, import.meta.url))` で起動します。Vite や webpack 5 などのバンドラーは、設定なしでこれを扱います。worker を起動できない場合はメインスレッドで編集が行われます。動作はしますが、大きな画像ではページが一瞬止まることがあります。

## Content Security Policy

Content Security Policy を使う場合は、次を許可してください。

- worker のための `worker-src 'self'`。
- `img-src blob:`。ビューアーは添付ファイルと適用の結果を `blob:` URL で表示するためです。

## 大きな写真

- **編集中**は、プレビューが約 2 メガピクセルのコピーで処理するため、どんな写真でも目盛りとツールは滑らかに動きます。
- **適用時**は、すべての変更がフル解像度で計算されます。大きな写真では数秒かかるため、その間ビューアーはメッセージを表示し、操作をロックします。
- **時間とメモリを節約するには**、[`maxOutputSize`](../reference/options#maxoutputsize) を設定します。2000 や 3000 ピクセルといった上限なら文書は読みやすいまま、適用が速くなり、ファイルも小さくなります。

## 受け付ける画像

`src` には、ページと同一オリジンの URL か、クライアントで添付された `File` または `Blob` を指定します。PaperPic は画像のピクセルを読み取りますが、ブラウザーは別オリジンの画像では CORS を使った場合にしかそれを許可せず、PaperPic は CORS を要求しません。画像は自分のドメインから配信するか、自分で取得して `Blob` を渡してください。

## サーバーサイドレンダリング

PaperPic にはブラウザーが必要です。Vue と React のコンポーネントは、Nuxt や Next.js などのサーバーでは空の要素を描画し、ブラウザーでビューアーを作成します。コアを使う場合は、コンポーネントのマウント時などに、ブラウザーでビューアーを作成してください。

## 対応ブラウザー

PaperPic は [Baseline Widely Available](https://web.dev/baseline) のブラウザーに対応しています。主要なすべてのブラウザーで 30 か月以上動いている機能の範囲です。パッケージはこの対象、つまり Chrome と Edge 124、Firefox 125、Safari 17.5 以降向けにビルドされているため、トランスパイルは不要です。
