# События

События сообщают вашему коду, что происходит в просмотрщике. Подписывайтесь на них через [`on()`](./methods#on). В Vue это события компонента, например `@apply`, а в React — props, например `onApply`. Если подписанная функция выбрасывает ошибку, просмотрщик продолжает работу: страница получает ошибку как любую неперехваченную, а остальные функции всё равно выполняются.

:::tabs key:framework
== JavaScript

```ts
pic.on('apply', ({ blob }) => upload(blob))
```

== Vue

```vue
<PaperPic :src @apply="({ blob }) => upload(blob)" />
```

== React

```tsx
<PaperPic src={src} onApply={({ blob }) => upload(blob)} />
```

:::

## `load`

- **Данные:** [`Size`](./types#size)

Изображение загружено и показано. `width` и `height` — его размер в пикселях. Срабатывает при каждой загрузке `src`, в том числе с [`reload()`](./methods#reload), но не после применения, результат которого приходит с [`apply`](#apply).

## `error`

- **Данные:** `{ error: Error, phase: 'load' | 'preview' | 'apply' }`

Что-то не удалось, и `phase` говорит что:

- `'load'`: изображение не удалось загрузить.
- `'preview'`: правку не удалось показать, например потому, что изображение слишком велико для браузера. Редактирование остаётся открытым.
- `'apply'`: изменения не удалось применить. Редактирование остаётся открытым.

## `change`

- **Данные:** [`PaperPicState`](./state)

Состояние изменилось — по действию пользователя или из-за вызова метода, например при масштабировании, открытии инструмента или отмене. Событие передаёт всё состояние, то же, что вернул бы [`getState()`](./methods#getstate) в этот момент. Применение вызывает его дважды: в начале, с `busy: true`, и при успешном завершении, после [`apply`](#apply).

Это меняет состояние, не вызывая `change`:

- Загрузка изображения, о которой сообщает [`load`](#load) или [`error`](#error).
- Неудачное применение, о котором сообщает [`error`](#error). `busy` снова становится `false`.
- `setOptions()` и props компонентов, чтобы двусторонние привязки не зацикливались.
- Изменение размера просмотрщика, которое меняет `zoom`, пока действует подгонка.

Перемещение изображения ничего не вызывает, потому что состояние не хранит его положение. [Состояние](./state#in-step) показывает, как синхронизировать свои элементы управления.

## `apply`

- **Данные:** [`ExportedImage`](./types#exportedimage)

Применение закончилось — с кнопки, по `Enter` или через [`apply()`](./methods#apply), — и результат уже на экране. `blob` содержит изображение в формате `type`, который выбирает [`output`](./options#output).

## `download`

- **Данные:** [`PaperPicDownload`](./types#paperpicdownload)

Изображение вот-вот будет сохранено кнопкой скачивания или через [`download()`](./methods#download). `source` — изображение на экране: результат последнего применения или, если его нет, `src`. `filename` — имя файла.

Вызовите `preventDefault()`, чтобы браузер не сохранял файл, например чтобы сохранить его иначе:

```ts
pic.on('download', ({ source, filename, preventDefault }) => {
  preventDefault()
  saveToCloud(source, filename)
})
```
